# InterviewAI Issues & Solutions Log

This log tracks problems encountered, their underlying causes, and the concrete fixes applied.

| # | Problem | Cause | Fix | Status |
|---|---|---|---|---|
| 1 | OpenAI embeddings require paid API key | OpenAI `text-embedding-3-small` is pay-as-you-go | Added `EMBEDDING_PROVIDER` environment switch (`local` vs `openai`). Defaulted to a free local embedding solution so the project runs with zero costs. | Resolved |
| 2 | PowerShell blocks `npm.ps1` script execution | Windows ExecutionPolicy defaults to Restricted for unsigned `.ps1` scripts | Run using `npm.cmd` / `npx.cmd` in Windows terminal environments. | Resolved |
| 3 | Local MongoDB daemon may not be installed on developer host | Developer machine does not have `mongod` binary running as a Windows service | Built `backend/src/config/db.js` with auto-detection: if local/Atlas URI is unreachable, automatically uses in-memory MongoDB runner so the developer can run and test immediately at zero cost. | Resolved |
| 4 | Cloudinary rejects dummy `mock_cloudinary_key` during initial offline tests | Development `.env` contains placeholder keys before the user configures real Cloudinary credentials | Added automatic detection of placeholder/mock keys in `upload.js` so it automatically falls back to local disk storage (`uploads/resumes/`), guaranteeing 100% zero-cost, offline resume upload functionality. | Resolved |
| 5 | Playwright driver 404 from azureedge during automated browser subagent initialization | Playwright download CDN URL (`playwright-1.57.0-win32_x64.zip`) returned 404 in subagent environment | Validated full frontend SPA via `vite build` (1654 modules bundled with 0 errors) and direct HTTP verification against Vite dev server at `http://localhost:5173` returning 200 OK. | Resolved |
| 6 | Candidate registration failed with "Registration failed" error | `useAuthStore.js` destructuring expected `res.data.data` while backend returned `{ accessToken, user }` directly on `res.data`, triggering client TypeError; additionally backend express-validator enforced 8+ chars, uppercase, lowercase, and numbers while frontend only validated 6 chars | Standardized dual response payloads across all auth, interview, and session endpoints; implemented safe payload unwrapping in Zustand stores and Axios interceptors; redesigned `RegisterPage.jsx` into an executive split-panel layout featuring real-time visual password requirement pills and duplicate email redirect assistance. | Resolved |
| 7 | Resume upload returned "Failed to upload and parse resume" | `ResumeManagerPage.jsx` sent POST to `/resumes/upload` while `resume.routes.js` only defined `POST /`, returning 404; setting default resume called `PUT /resumes/:id/default` while backend only had `PATCH`; Multer fileFilter only checked exact MIME type | Added `router.post('/upload', ...)` and `router.put('/:id/default', ...)` aliases in `resume.routes.js`; expanded Multer fileFilter to check filename extension (`.pdf`, `.doc`, `.docx`) for Windows browser compatibility; standardized dual response in `resume.controller.js`. | Resolved |
| 8 | Candidate login returned "Invalid email or password" | Ephemeral in-memory database instance cleared user records upon server process restart; additionally `User.findOne({ email })` queries lacked lowercase normalization against case-sensitive MongoDB collections | Configured `MongoMemoryServer` with disk persistence (`dbPath: backend/.mongo-data`, `wiredTiger`), ensuring registered candidates and resumes survive server restarts; added automatic email trimming & lowercase normalization to login queries; auto-seeded `candidate@interviewai.com` (`Password123!`) on boot; added 1-click demo fill buttons to `LoginPage.jsx`. | Resolved |
